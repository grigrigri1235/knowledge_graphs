## Objective
When the guard blocks, tell the agent which fact of the rule is not met, what the evidence is, and what makes it
true. No hand-written text per fact. The message comes from:
- the rule table (p2);
- the policy sentences each rule cites (from the rule set);
- the fact definitions (p5): source, parts, `who`, evidence.

## The message
```
BLOCKED by policy guardrail. The <tool> call was NOT executed.          (unchanged first line)
Policy: "<the policy sentence(s) the rule cites, quoted from the rule set>"
Not met:
- <the fact's parts with their values, e.g. "order #W1 looked up: no" / "gift card balance $17.00 < price
  difference $32.00">, the value that breaks the rule.
What makes it true:
1. <advice, picked by the fact's `who` (p5)>
<closing line>
```
- The text comes from the policy itself and from the fact's parts and evidence: the database values read, the
  missing event, the quoted words. **Never from the rule set's predicate descriptions**, which keep the old "an
  earlier tool output shows ..." framing.
- For a negated fact (for example "the reply offers compensation"), the line shows the value that breaks the rule
  (true), not "false".

| `who` (p5) | advice |
|---|---|
| `agent` | do this step first (for example log in, look order #W1 up, list the details), then try again |
| `ask` | ask the user this (the policy tells you to); if yes, try again; if no, do not |
| `user_only` | this depends only on what the user says; do not lead the user to say it; without it this action is not allowed |
| `none` (database, arguments) | not possible with these arguments; this is the value that fails |

- The facts to name come from the rule table. When a rule has several ways to hold, every way is named, **except**
  ways that need a `user_only` fact the user has not given. Those are not offered as advice. In stand-in runs
  (`meaning = saved_judge`), a judge "unknown" is looked up as its blocking value and shown as "not established".
- **Closing line:**
  - "Do not repeat the same call as it stands" appears when no `agent` or `ask` step can make the rule hold, and
    after a strict "no" from the user;
  - otherwise: "When this is done, call <tool> again."
- **Safety:**
  - before login, no database value appears (info classes, p7);
  - after login, only data of `me`;
  - no judge text is quoted, because there is no judge.
- **Simplest version** (`messages = simple`), for comparison: TGR's own message without its closing "violated, do not
  repeat" line.
- **Fallback:** any exception → TGR's own message, counted. Without it, one exception would make `TGR.step` retry the
  whole step 3 times and then raise.

## How we know it is right, without a person
| check | label | pass |
|---|---|---|
| every value in a message is true | a separate, few-line database reader (not the fact expressions), and the event log | 0 failures |
| every suggested step is a real call | τ-bench's tool schemas. Steps whose arguments the guard knows (a look-up by id) are also run on a copy, with no Error. For steps whose arguments only the user knows (the login's email), only the tool and argument names are checked | 100 % |
| a "not possible" line matches τ-bench's own refusal | the tool check of p3 | 100 % on the facts it decides |
| no leak before login, no other user's data | a raw scan: every string field of every database record against the message's tokens (not the info classes) | 0 |
| no advice that leads the user | no `user_only` fact offered as a step | 0 |
| no "do not repeat" when a step can fix it | the rule table: an `agent` or `ask` flip set exists and the user gave no strict "no" | 0 |
| the message changes no decision | `mln.decide`, the same values with `frozen`, `rule` and `simple` | 100 % equal |
| the code never fails | the fallback count | 0 |
| length | character counts | reported only |

Counts for the user, one class per block: the advice class, and whether the closing forbids the same call.
