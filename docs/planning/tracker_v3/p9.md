## Objective
One new guard, `TrackerTGRv3`, that sets every fact from p6-p8 and never calls the full judge. TGR's own decision code
and rules are unchanged. The eval v2 guard stays byte-identical.

## Design
- `guard/tgr_tracker_v3.py`, class `TrackerTGRv3(TrackerTGR)`, `NAME = "tgr_tracker_v3"`.
- **Three switches**, stored in every record:
  - `facts`: v2 = eval v2's tracker; v3 = the facts of p5-p7;
  - `meaning`: saved_judge = the judge's saved answers, offline only, as a stand-in until p12; tiny = the tiny
    questions of p8;
  - `messages`: frozen, rule, simple (p10).
- **It overrides three hooks:**
  - `_judge`: no LLM judge call. Facts come from code and the tiny questions;
  - `tracker_values`: builds the state, and keeps it for the message;
  - `_feedback`: the message (p10).
- **On a state error** (replay mismatch, parse problem): the affected facts take the blocking value, and the record
  counts it. There is no judge fallback (Q1).
- **`FROZEN_SHA256`** lists every new v3 file, and the v2 files with their known hashes, so a changed file stops a v3
  run.
- **Registered only in new files:** `fork/offline_v3.py` now, and `guard/run_online_v3.py` in p13. The v2 registries
  are not touched.

## Steps
1. Write the guard.
2. Tests `tests/test_v3_guard.py`, with fake answers:

   - a state error → the blocking value, counted;
   - the record holds the switches;

3. Add the guard to `fork/offline_v3.py`.

## New files

## How we know it is right, without a person
- **Decisions come from TGR's own code** (`mln.decide`, unchanged).
  - With v3 facts and tiny answers, every value is true or false, so the result is exact (no sampling).
  - In the stand-in runs (`meaning = saved_judge`, or `facts = v2`), the judge's saved "unknown" answers are kept as
    they are, and TGR's own three-valued decision handles them, as in eval v2. The saved judge value stands in only
    for the tiny-question answer, wherever p5's definition uses one; code parts stay code. With several unknowns in
    an OR rule, the stand-in can allow where v3 would block. The unknowns per check are counted,
    and `PYTHONHASHSEED` is fixed.
- **0 judge calls**, by test.
- **With `facts = v2` and `meaning = saved_judge`,** the guard reproduces eval v2's saved decisions on the development data (Gate 0 of p1).
