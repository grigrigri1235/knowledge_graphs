## Objective
Write down, for every one of the 66 facts of the frozen rules, exactly how code sets it: its source, its start
value, its update rule. Two values only, true or false. This file is the contract that p6-p8 implement.

## The fact sources
| source | how it is set | when there is nothing yet |
|---|---|---|
| database | read from the database copy at the check | not possible: the database always has a value. A nonexistent id is false |
| event | false until the event happened (a tool call that worked) | false |
| call arguments | read from the pending call | a missing argument takes the blocking value (p2's `blocking_values`), and is counted |
| text structure | code on the text: exact strings, ids, positions | false |
| tiny question | a saved yes/no answer about one or two messages that code picks (p8) | false; "unclear" takes the blocking value |

A fact may combine parts with AND / OR, for example "the user confirmed the cancellation" = (code: an agent message
names this order and reason, then the user replies) AND (question: the reply agrees). The frozen rules are not
changed: they read the combined fact.

## Rules for writing the definitions
1. **Written from the policy text**, never from the judge's answers or the gold scorer. Each entry cites its policy
   sentence.
2. **World conditions come from the database** (balance, status, cabin, insurance, membership, availability). The
   eval v2 harm came from reading these as "was it shown".
3. **A "looked it up first" event part only where the policy says to check first** (Q4):
   - retail order status ("you should check its status before taking the action", lines 35 and 43);
   - airline modify and cancel ("the agent must make sure", lines 44 and 58).

   Example: `order_status_checked_pending` = event (the agent looked order X up) AND database (X is pending **at the
   check**, so a later change of the order is seen).
4. **Fixed readings** (each with a test, from the earlier critics):
   - the signed price difference: a refund needs no gift-card balance;
   - each tool's own rounding for the gift-card difference (exchange rounds to cents; modify does not);
   - an exchange for the same item is blocked (the policy says "different option");
   - the reservation's cabin is replaced by the last flight update (τ-bench never updates the cabin field);
   - a past segment with status "cancelled" was not flown;
   - "not a gift card": the gift-card balance fact is false, and the rule's other branch holds.
5. **A missing field of an object that exists is a bug.** It is counted, and never turned silently into a value.

6. **Who can make the fact true** (field `who`, read from the policy sentence; the messages use it, p10):
   - `agent`: an agent step makes it true (log in, look up, list the details, remind);
   - `ask`: the policy tells the agent to ask the user (confirmation, payment choice, insurance choice);
   - `user_only`: only the user's own words make it true, and the agent must not lead them (a complaint, a request for
     compensation, a health reason);
   - `none`: the database or the call's arguments decide it.
