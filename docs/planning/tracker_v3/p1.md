# Part 1: Freeze eval v2, rebuild every saved decision, set the hold-out aside ($0)

> **STOP BEFORE REAL MONEY.** No paid LLM call and no network call without the user's new, explicit approval for
> that exact step. This part has no money in it.

## Objective
Before anything new is built:
- prove that eval v2 stays frozen;
- build the one offline base that every later part uses, which re-decides saved checks with the guards' own code and
  the saved values;
- split the data into development data and a hold-out.

## Steps
1. **Manifest** `output/eval_v3/manifest_eval_v2_data.sha256`: the sha256 of
   - every file under `output/eval_v2/`;
   - every `output/online/p10_*/` episode file;
   - every used `from_shieldagent/runs/` episode file (train and val only; the partner's test group is listed as
     excluded);
   - the frozen method files: `state_tracker/lookups_*.json`, `lookup_format.py`, `output/predicate_types.json`,
     `from_shieldagent/rules/`, `guard/tgr_tracker.py`, `guard/run_online.py`, `guard/soft_stop.py`,
     `fork/points_tgr.py`, `state_tracker/replay.py`, `state.py`, `tau_copy.py`, and the runner copy's
     `feedback.py`, `runtime.py`, `mln.py`, `judge.md`, `episode.py`.

   The method-file hashes are checked against the hashes eval v2 recorded. Git is no help here: these files are
   untracked.
2. **The partner's repo, read-only:** record `~/ShieldAgent`'s HEAD (`GIT_OPTIONAL_LOCKS=0 git log`), and check
   that no guard, rule or runner file changed since `1bacdb0`, our copy. On 2026-10-22 the 3 newer commits changed
   only docs and `scripts/reproduction/p1_trace.py`. Never write there.
3. **Test** `tests/test_v3_frozen.py` recomputes the manifest. Every later v3 script runs the same check at start and
   stops on any change.
4. **No gold:** extend `tests/test_no_gold_import.py` to every new v3 file. Nothing in v3 imports the gold scorer.
5. **Offline base** `fork/offline_v3.py` (new; `fork/points_tgr.py` is not edited): for one saved check, it rebuilds
   the state (`build_state`), gives the guard the saved values, and returns:
   - the decision, margin and violated rules;
   - every fact value with its source;
   - the block message.

   Guards: `frozen` (frozen TGR) and `v2` (TGR + tracker). Later parts add v3.
6. **Gate 0, reproduction**, on every saved judged check:
   - Stage A 2,000 conversations, our 495, the partner's 495 (train + val): 38,579 judged checks and 4,885 blocks;
   - plus the 415 cap-override checks (decision only);
   - plus the 3,260 judged Stage B checks after the forks.

   The source guard's offline decision, margin, violated rules and block-message bytes must equal the saved ones;
   for v2 sources, the tracker values too.
7. **Length per check:** the history length, measured exactly as the judge's view measures it
   (`len(render_history(executed[:executed_prefix_len]))`, runtime.py lines 43 and 127). Bins: < 12,000 /
   12,000-24,000 / > 24,000 characters. Per conversation: the largest length.
8. **Task key** on every check: (domain, split, task id, trial). Assert that no check comes from the partner's test
   group. Our 495 and the partner's 495 are the **same (task, trial) pairs**, so they are one paired set.
9. **Development data and hold-out:**
   - **hold-out:** the val conversations (198, strong agent: our 99 `p10_luna_val` + the partner's 99 `luna_val`),
     plus the Stage B tries forked from them (1 fork, 8 tries). They are used only in Gate 0 here, and once in p12;
   - **development data:** everything else.
10. **Pre-registration** `output/eval_v3/preregistration.md`, part 1: the pass marks of p1-p3, copied from the part
   files. Its sha256 is logged before any v3 output exists. p4 adds part 2 (the pass marks of p4-p12) before any p5
   output exists, and p13 links the online one. It has a **change log**: a change to a v3 file after its sha256 was
   recorded gets a dated line with the reason. Changes are allowed only on development data. Pass marks never change.

## How we know it is right, without a person
- **The manifest test** passes before and after the part.
- **Gate 0:** 100 % of saved decisions and block messages reproduced. Eval v2 reached this before (5,793 / 5,793,
  7,555 / 7,555, 4,903 / 4,903 decisions; 417 / 417 messages).
  - Each miss is either a bug (fixed), or one of two listed miss classes: a "source-run fallback" (a silent tracker
    fallback in the p10 online runs, from the time of the thread race), or a judge call that failed and was retried.
  - Hard cap: at most 0.5 % of checks per data set. Above it, the part fails.
