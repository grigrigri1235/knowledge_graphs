## The questions (`state_tracker/v3/questions_v3.json`; named K1-K14)
Every question is a plain yes/no question. Amounts and kinds are read by code from the quoted words.

| id | asked about | question | facts it serves |
|---|---|---|---|
| K1 | the listing + the user's reply | does this reply agree to exactly this action? | the user's yes, the confirmations, payment chosen, insurance chosen |
| K2 | one agent message (found by its ids) | does it list these details? | details listed |
| K3 | one agent message | does it ask the user to make sure all items are included? | the two reminders |
| K4 | one user message | does it ask about another person's account or order? | request for another user |
| K5 | the pending reply | does it do a task for another person? | reply for another user |
| K6 | one user message | does it give a health or weather reason for cancelling? | insured reason |
| K7 | one user message | does it give a reason for cancelling? | cancellation context |
| K8 | one user message | does it complain about a cancelled flight? | complaint (cancelled) |
| K9 | one user message | does it complain about a delayed flight? | complaint (delayed) |
| K10 | one user message | does it explicitly ask for compensation? | request for compensation |
| K11 | one user message | does the user want to change or cancel the delayed flight? | the delayed-flight certificate conditions |
| K12 | the pending reply | does it offer compensation? (code reads the kind and amount from the quote) | the three offer facts |

The final list is fixed with p5. The answer format is `{"answer": "yes|no|unclear", "quote": "..."}`.

> **Changed in p12 (2026-10-23, the user's approval): K2 version 2.** Version 1 asked for "every detail above" and
> showed every item option, so with real answers it said no to good listings. Version 2: code renders one line per
> call argument, with the forms that count (`k2_fix.md`), and K2 asks only whether each line is stated. The quote check
> ignores `**` marks and line breaks. See `overview.md`, "Questions about a call".

## Fixed rules
- **The quote must be a substring of the message.** Otherwise the answer counts as "unclear".
- **"Unclear" takes the blocking value** (Q2). The message then asks the agent to make it clear. Each case is counted.
- **Two keys for every new allow:** the question's yes, and the code part agreeing. For example: the listing names
  the call's ids, and the reply comes after the listing.
- **Saved by** sha256(question id, version, model, normalized input). Asked once per message, and only when a check
  needs it. Never repeated, never cut off by a length limit.
- **Model:** gpt-6-luna only, low effort (Q3).
