# Part 9: Action-Based Rule Circuit Construction

## Objective
Organize safety rules into independent, action-specific subgraphs called **Rule Circuits** ($G_{\text{ASPM}}[p_a]$).

> [!NOTE]
> **SPECIAL MODIFICATION (Baseline Graph First):**
> We are deliberately bypassing Verifiability Refinement (VR) and Redundancy Pruning (RP) for this run to build the **initial baseline ASPM graph** directly from the **raw extracted LTL rules** (`output/wiki_extracted_ltl_rules.json`).
> - **Goal:** Establish a genuine unoptimized baseline graph to test how the system performs out-of-the-box, allowing us to later measure exactly how much VR and RP improve (or degrade) graph quality and guardrail efficiency.
> - **Input Source:** `output/wiki_extracted_ltl_rules.json` (25 rules, 53 predicates).
> - **Output Artifact:** `output/wiki_action_circuits.json` (Baseline Action Circuits).

### Important Difference from Part 8 (RP):
- **Part 8 (RP)** was about **merging duplicates**: finding predicates that meant the exact same thing (like `is_private` vs `is_confidential`) and deleting redundant copies to shrink the rule set.
- **Part 9** is about **modularizing into topic circuits (no deletions)**: keeping all unique predicates intact, but grouping related rules into isolated circuits per action (e.g., a dedicated circuit for `cancel_order`, another for `modify_order`). This ensures the guardrail only needs to verify the small subset of rules relevant to the specific action being executed, rather than evaluating the entire rule base every turn.

---

## Subtasks
1. **Adjacency & Similarity Matrix ($A$):**
   - Implement `src/circuit_builder.py` to build an adjacency matrix $A \in \{0,1\}^{|P_s| \times |P_s|}$ across all state predicates.
   - Set $A_{ij} = 1$ if state predicates $(p_s^i, p_s^j)$ co-occur in any rule OR have high semantic similarity (cosine similarity $\ge \theta$); otherwise $0$.

2. **State Predicate Clustering:**
   - Apply spectral clustering on matrix $A$ to divide state predicates into $k$ topic clusters.
   - If two state predicates appear together in the same rule but landed in different clusters, merge those clusters to keep co-dependent conditions together.

3. **Action Circuit Assembly:**
   - Group the rules into rule clusters based on the state predicates they contain.
   - For each target action predicate $p_a \in P_a$ (e.g., `cancel_order`, `modify_order`, `exchange_order`, `modify_shipping_address`), attach all relevant rule clusters to form its dedicated action circuit:
     $G_{\text{ASPM}}[p_a] = \bigcup C_r^\ell$.

4. **Output Serialization & Circuit Stats:**
   - Save the assembled circuits to `output/wiki_action_circuits.json`.
   - Log circuit statistics: list each target action, the number of isolated rules in its circuit, and the reduction in verification overhead.
