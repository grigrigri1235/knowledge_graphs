# Part 8: Redundancy Pruning (RP)

## Objective
Implement and execute Redundancy Pruning (RP) to cluster semantically similar predicates, eliminate duplicates, and merge redundant rules using `docs/file_formats/rp_prompt.md` and `docs/file_formats/rule_optimization_format.json`.


## Subtasks
1. **RP Script Development:** Create `src/merger_rp.py` to identify semantically similar predicates and redundant rules, prompting the model to merge them into unified representations.
2. **Dry-Run Prompt Preview:** Verify prompt assembly via `--dry-run` saved to `output/wiki_rp_prompt_preview.txt`.
3. **Execution & Pruning:** Run `src/merger_rp.py` on `output/wiki_vr_refined_rules.json` to produce `output/wiki_optimized_rules.json`.
4. **Optimization Metrics:** Explicitly measure and report the following metrics comparing the rules across three stages: (1) Raw Extraction, (2) After Verifiability Refinement (VR), and (3) After Redundancy Pruning (RP):
   - **Number of Predicates:** Total count of unique atomic decision variables ($P$).
   - **Number of Rules:** Total count of active LTL rules ($R$).
   - **Average Rule Vagueness Score:** Concrete rating measuring ambiguity (lower is better, calculated via predicate similarity and LLM evaluation).
   - **Pruning & Reduction Rate (%):** Percentage reduction in predicates and redundant rules achieved by the pruning step.
   - Summarize findings in a clean comparison table in `output/wiki_rp_review.md`:
     `| Stage | # Predicates | # Rules | Avg. Vagueness | Reduction % |`
