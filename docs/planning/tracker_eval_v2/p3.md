## Objective
The code that finds fork points, rebuilds a conversation at a fork point, and continues it in one branch.

## Subtasks
1. **`fork/find_points.py`:** for a set of conversations, find the first attempt where frozen TGR and TGR + tracker
   decide differently. If the agent retried a blocked action, the fork is at the first try. How it works per source:
   - **frozen TGR conversations:** compute the tracker's decision offline (as in the earlier plan's Part 8, version
     b);
   - **TGR + tracker conversations:** compare `tracker.judge_values` with the values that were used.

   Output, per fork: source, agent, domain, task, try, step, attempt, action, both decisions, the kind ("block
   removed" or "block added"), the predicates that changed, and the reviewer's verdict where there is one.
2. **`fork/rebuild.py`:** `rebuild(fork_point)` returns, at the fork attempt:
   - the database (replayed);
   - the agent's messages;
   - the user simulator's messages;
   - the guard state (trace, blocks in a row, executed actions);
   - the task.
3. **`fork/run_branch.py` and `fork/run_all.py`:**
   1. apply the branch's decision at the fork attempt (allow: run the action; block: give the guard's message);
   2. continue the normal loop with the branch's guard (A: frozen TGR; B: TGR + tracker), with fresh LLM calls and
      the source run's profile;
   3. score the conversation with τ-bench at the end, and save it;
   4. resume where it stopped, with the same safety checks and the same soft stop as the wrapper.
4. **Rebuild checks on the saved conversations** (sources 1 and 2). For every fork point:
   - the replayed database gives the saved tool outputs;
   - the rebuilt agent messages equal the saved ones up to the fork;
   - the rebuilt user-simulator messages match the user turns;
   - frozen TGR at the fork attempt gives the saved decision.

   Output: `output/eval_v2/checks/rebuild.md`.
5. **Tests** in `tests/test_eval_v2_fork.py`, with a fake LLM:
   - both branches start from the same state;
   - they differ only in the fork decision and the guard after it;
   - the limits continue from the rebuilt counts;
   - the score is computed from the final database.

## Done when
- The tests pass, and the rebuild checks pass for every saved fork point, or a fork point is dropped with the reason
  written down.
