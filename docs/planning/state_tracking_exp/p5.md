# Part 5: Lookups (Format, Fact or Shown, Independent Check)

## Objective
For each predicate whose type is set by code (Part 3), write one lookup that computes its value from the state
(Part 4).

## Format
- One Python expression per predicate. It may use only these names:
  - `args`: the pending call's arguments;
  - `db(kind, id)` and `db_all(kind)`: objects in the database copy (*fact*);
  - `shown(kind, id)` and `shown_all(kind)`: the version shown in the conversation, or `None` (*shown*);
  - `events(tool=..., ok=True)`: earlier tool calls;
  - `today` and `date(text)`: dates.
- Also allowed:
  - comparisons, `and`, `or`, `not`;
  - `len`, `sum`, `any`, `all`;
  - simple list comprehensions;
  - indexing on dicts and lists (`x["field"]`, `x[0]`) and `.get(field)`.
- A validator (`state_tracker/lookup_format.py`) reads each expression with Python's `ast` module and rejects
  anything else: no imports, no other functions, no other attributes, no assignments.
- The result is true, false or unknown.

## Each lookup states
| field | meaning |
|---|---|
| `uses` | `fact` or `shown`, chosen from the predicate's description. "Earlier tool output establishes …" means `shown`. |
| `if_missing` | the value when a needed object or field is missing: `false` or `unknown`, again from the description. For example, "earlier tool output establishes X" with no such output gives `false`. |
| `plain` | one plain-language sentence, for example "true if the order in the call was shown with status pending". |
| `reason` | why this lookup matches the description. |

## Subtasks
1. **Write the validator and the evaluator,** with tests (`tests/test_lookup_format.py`).
2. **Write the lookups:** `state_tracker/lookups_airline.json` and `lookups_retail.json`, with the fields above. I
   write them from the predicate description only, not from the judge's values or gold code.
3. **Independent check:** a new agent, not the one that wrote the lookups, gets only the predicate descriptions,
   the lookups and the format. For each lookup it:
   - checks `uses`, `if_missing` and the expression against the description;
   - runs the lookup on 2–3 saved steps (one true, one false, one unknown or missing case, where they exist), and
     checks each result against the conversation.

   Output: `output/p5_independent_check.md`. Every problem it finds is fixed or explained.
4. **Freeze:** record the date and the sha256 of both lookup files in `overview.md`.

## Rule after the freeze
A lookup may change only to fix a clear bug. Every fix is logged in `output/p5_lookup_fixes.md`, with the case that
showed the bug. Part 6 is then run again, and the report shows both versions.

## Deliverables
- `state_tracker/lookup_format.py` and `tests/test_lookup_format.py`.
- `state_tracker/lookups_airline.json` and `state_tracker/lookups_retail.json`.
- `output/p5_independent_check.md`.

## Done when
- The independent check is done, every problem is fixed or explained, and the lookups are frozen.
