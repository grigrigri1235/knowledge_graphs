# Part 8: Effect on Decisions

## Objective
Count how many guard decisions would change if code computed the values that code can compute.

## Subtasks
1. **Check the copied decision code first.** Using the judge's own values, run the copied decision code
   (`repro_runtime/mln.py::decide`; ε = 0.1, all weights 1; rules turned into the needed format by
   `state_tracker/tgr_to_aspm.py`) on every saved step. It must give the same decision as the saved one on every
   step. If not, stop and report.
2. **Replace and decide again.** For each step:
   1. take the judge's values;
   2. replace the code-type values with the tracker values;
   3. run the decision again.

   Do this in two versions, which differ only when the tracker gives unknown:
   - **(a)** a tracker unknown stays unknown;
   - **(b)** a tracker unknown is replaced by the judge's value.
3. **Count, for both versions:**
   - blocks that go away and blocks that are added;
   - per run, per domain, and per predicate.

   The version with fewer wrong blocks (using Part 7) is the one Part 10 uses. It is chosen before Part 10 starts.
4. **Use the Part 7 results** to estimate how many changes fix an error and how many add one.
5. **Write the results** to `output/p8_decision_changes.md`.

## Limit
We count only the decision at each saved step. After a changed decision, the real conversation would continue
differently. Part 10 measures that with new conversations.

## Deliverables
- `state_tracker/decide_again.py` and `output/p8_decision_changes.md`.

## Done when
- Check 1 passes, and the counts are written.
