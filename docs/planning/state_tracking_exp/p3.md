# Part 3: Give Each Predicate One Type

## Objective
Give each of the 66 frozen TGR predicates (42 airline, 24 retail) exactly one type, or mark it "mixed". The type
decides who sets the value: code or the LLM.

## Types
| type | the value depends on | set by |
|---|---|---|
| argument | only the pending call's arguments | code |
| database fact | objects in earlier tool outputs (the arguments say which object; dates and amounts may be compared) | code |
| event | only which tool calls ran before, and whether they worked | code |
| conversation | only what a user or agent message means | LLM |
| mixed | the meaning of a message, plus something code can check | LLM in this plan; to be split later (idea A2) |

How to choose the type: use the questions in `overview.md` ("How we decide what is a predicate").

## Subtasks
1. **Draft:** I give each predicate a type, from its description and its evidence sources, with a one-line reason.
   - `output/predicate_types.json`: machine-readable.
   - `output/predicate_types.md`: a table for review.
2. **Review:** you check the table and correct it. The types are frozen after your OK, and the date is recorded in
   `overview.md`.
3. **Count,** using the Part 2 records:
   - how many predicates fall in each type;
   - how many judge values fall in each type;
   - how many of the values that caused a block fall in each type;
   - **the share of blocks that involve at least one code-type predicate**, per run and domain.

   This share is the upper limit on how many blocks the tracker can change. It is tracked as a metric; there is no
   stop point. Output: `output/p3_type_counts.md`.

## Note
The draft is LLM work, so a person's review is required before Part 5.

## Deliverables
- `output/predicate_types.json`, `output/predicate_types.md` and `output/p3_type_counts.md`.

## Done when
- You have approved the types.
