# Part 4: State Tracker (Database Copy, Replay Check, Shown Set, Event Log)

## Objective
For any step in a conversation, build the state before that step, using only code:
- **database copy:** τ-bench's data files, updated by running τ-bench's tool code for each executed call;
- **shown set:** the objects (kind and id) that appeared in tool outputs, with the version shown;
- **event log:** each executed tool call: step, tool, arguments, worked or failed, and the output;
- **today's date:** read once from the policy text.

See "The rolling state" in `overview.md`.

## Subtasks
1. **Tool table.** From the copied τ-bench tool code (Part 1), write down for each tool:
   - whether it changes the database;
   - which kind of objects its output contains, and their id field (for the shown set).

   Output: `state_tracker/tool_table.json`, with notes in `output/p4_tool_notes.md`. This uses τ-bench code only,
   never gold code.
2. **Write `state_tracker/state.py`:**
   - `load_db(domain)`: a fresh copy of the data for each conversation;
   - `build_state(history, action)`: replays the executed tool calls in the history, in order, and returns the
     database copy, the shown set, the event log and today's date.

   Blocked calls are not in the history (Part 2), so they are not replayed.
3. **Replay check.** For every executed call in all Part 2 conversations, our replayed output must equal the saved
   output. Save the result to `output/p4_replay_check.md`: the number of calls checked, the number that match, and
   each mismatch with its cause.
4. **Unit tests** (`tests/test_state.py`), on short hand-made conversations:
   - a call that changes the database (for example, a cancel) changes the copy;
   - a failed call ("Error…") is logged as failed and changes nothing;
   - the shown set keeps the newest version of an object;
   - a list output (for example a flight search) adds every object in the list to the shown set;
   - each conversation starts from a fresh copy (no leftovers from the previous one).

   The expected values are plain facts of the input, not judgements.
5. **Shown-set report:** list tool outputs that could not be parsed into objects, and unknown tools, in
   `output/p4_parse_report.md`.

## Deliverables
- `state_tracker/tool_table.json`, `state_tracker/state.py` and `tests/test_state.py`.
- `output/p4_tool_notes.md`, `output/p4_replay_check.md` and `output/p4_parse_report.md`.

## Done when
- The tests pass (output in `output/logs/p4_tests.log`).
- Every replayed output equals the saved one, or each mismatch is explained.
- Every parse failure is listed and explained.
