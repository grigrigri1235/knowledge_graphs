What a rule can check. The guardrail sees one pending action at a time, before it is executed, together with the conversation so far.
- A condition must be decidable before the action is executed. Never require a fact that only the action's own result can reveal (for example, details that the pending call itself retrieves).
- If a requirement applies only in some situations, put the situation into the condition: "X IMPLIES (NOT situation OR requirement)". Each predicate states one checkable fact; its description contains no "if".
- When the policy requires the agent to obtain information (ask for it, collect it), the precondition is that the information is known from the conversation (stated by the user or returned by a tool), not that a particular question was asked or who stated it. Requirements to inform, offer, remind or ask for a decision are about the agent's or the user's messages and stay as they are.
- When the policy requires the user to provide, choose or decide something, the precondition is that the user's choice is established: the user stated it, or the user agreed to an option the agent presented. Do not require that the user typed the value or that the agent used particular wording.
- A prohibition ("never do X to/for Z", "deny requests about Z") becomes "X IMPLIES NOT forbidden_situation", with a predicate that is true when the conversation shows the forbidden situation. Do not turn a prohibition into a proof obligation ("X IMPLIES allowed_situation_established") unless the policy itself requires the agent to check or establish that condition before the action.
- A precondition may require that something happened before the action, but not that earlier steps happened in a particular order (for example, that one question was asked before another): an order of past steps cannot be repaired when the action is checked.
- Rules on "respond" are only for specific restrictions on what a single message may do (for example, disclosing a certain kind of information before a precondition holds). Requirements on the general quality of every message (truthfulness, grounding, tone, subjectivity, helpfulness) and on which requests should be refused cannot be checked as restrictions on one action: write no rule for them.
- Requirements on how actions are combined within one turn (several tool calls at once, a message together with a tool call) cannot be checked one action at a time: write no rule for them.
